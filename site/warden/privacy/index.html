Warden for Mac

Warden privacy

Updated 16 November 2026. This covers Warden for Mac (the app and its background helper), version 1.1.0 and later. Anything that's new in 1.1.1 says so.

#The short version

  • Warden sends nothing about you or your Mac. It has no analytics, no crash reports, no ad or tracking code, no account and no device ID.
  • What it reads stays on your Mac, in ~/Library/Application Support/Warden.
  • It connects to other computers in three ways only, all listed below: the update check, PR names from GitHub, and checks from outside that you add yourself. Offline mode (1.1.1 and later) turns off all three.
  • You can check all of this yourself. See Check it yourself.

Checks of a server on this Mac (localhost, 127.0.0.1) never leave it.

Who receives these requests:

  • istari-ai.dev is served by Cloudflare Pages. We keep no logs of these requests. Cloudflare's dashboard shows us only totals, such as requests per day and per country. Cloudflare's own privacy policy covers what it handles as the host.
  • GitHub: your gh requests go to GitHub under your own GitHub account and GitHub's terms. We never see them.
  • Checks from outside go only to the addresses you typed.

Programs Warden runs for you (the services you add, such as a dev server or a cloudflared tunnel) make their own connections. Those are that program's connections, not Warden's.

#What Warden doesn't do

  • No outside code that phones home. It has no analytics, telemetry, crash-reporting or ad code. The only outside code in it is Sparkle, the open-source update framework many Mac apps use.
  • Sparkle's system profile is off. Sparkle can send the Mac's model, macOS version and CPU type with each update check, but only when an app turns that on (SUEnableSystemProfiling in its Info.plist). Warden doesn't, and a test checks that it never does.
  • Nothing it reads is ever sent: file and folder names, program names, window titles, coding sessions, logs and settings all stay on your Mac.
  • It sends no crash reports itself. macOS can send crash reports to Apple for any app, if you allowed that in System Settings → Privacy & Security → Analytics & Improvements. That's a macOS setting, not Warden's.
  • No account, sign-in or licence check.
  • Nothing is sold or shared. We have nothing to sell: Warden collects nothing.

#What Warden reads on your Mac

It needs these to do its job, and none of it leaves the Mac:

  • Running programs: their names, memory, CPU, what started them, and which folder they run in.
  • Disk usage: the sizes of folders it measures, git status of your repositories, and what version control ignores.
  • The files coding tools keep for their sessions (Claude Code, Codex, Gemini CLI and others): titles, folders and how to resume, for memory cards and Past work.
  • With the Accessibility permission (optional): which app and window are in front, and whether an app has stopped responding. Window titles can appear in "Stale work". From 1.1.1 you can turn that off (Settings → Privacy → Read window titles for Stale work), and then Warden never reads them.
  • Your Downloads folder, only if you turn on clearing installers you've already used.

Everything is in ~/Library/Application Support/Warden:

Settings → Uninstall → Delete Everything removes all of it, along with the app.

#Offline mode (1.1.1 and later)

Settings → Privacy → Offline mode, also offered the first time Warden opens. While it's on:

  • No update checks on its own. Check for Updates… in the Warden menu still works when you choose it.
  • GitHub isn't asked for PR names. Memory cards keep the PR number and title git already has.
  • Checks from outside don't run, so a service is never counted as down, or restarted, because of them. Checks on this Mac carry on.

Everything else works the same.

#Check it yourself

The list Warden keeps (1.1.1 and later). Settings → Privacy → "Connections Warden made" shows every address it reached, why, how many times and when. The terminal prints the same list:

shell
warden connections

What's open right now. This normally prints nothing:

shell
lsof -nP -i | grep -i warden

Over days. A firewall such as LuLu (free and open source) or Little Snitch shows every connection any app makes, and can block them. You'll see Warden reach istari-ai.dev about once a day, and nothing else unless you set up the other two.

The download itself. SECURITY.md shows how to check its SHA-256 and Apple's notarization.

#On a work Mac

  • No admin rights needed. Warden installs into Applications and runs as you, and its helper is listed under System Settings → General → Login Items.
  • Not sandboxed, and here's why: to see every program's memory, slow down or stop the ones you choose, and clear build folders, it has to see beyond its own folder. Anything that stops a program or deletes files starts off until you turn it on. For how Warden is signed and how its updates are checked, see SECURITY.md.
  • To block updates across a network, block istari-ai.dev/downloads/warden/appcast.xml, or turn on Offline mode on each Mac.

#Changes to this policy

Any change is listed in Warden's changelog and release notes, and the date at the top changes with it. A new kind of connection would be listed here and in the release notes before the version that makes it ships. A test in Warden's code fails if one is added without that.
