Warden security

How Warden is built, signed and updated, how to check your copy, and how to report a problem. For what Warden sends (nothing about you) and what it keeps, see PRIVACY.md.

#Report a problem

Write to security@istari-ai.dev. Please include:

  • the Warden version (Warden → About Warden);
  • the macOS version;
  • the steps that show the problem.

Please don't post it publicly until a fixed version is out. Fixes for security problems ship as soon as they're ready, without waiting for the next planned release, and the changelog credits you if you'd like.

#Supported versions

Only the latest release gets fixes. Installed copies update themselves (see Updates), so you're on the latest after the next check. Releases are listed in the changelog.

#How Warden is signed

  • Developer ID. Every piece of code is signed as Developer ID Application: Rajnish Kumar (23MPNLMYKW): the app, its helper and Sparkle.
  • Hardened runtime. It's on for the app and the helper.
  • Notarized by Apple. Apple scanned the app and the .dmg for malware before release, and the notarization ticket is stapled to both, so macOS can check it without going online.
  • Checked before each release. scripts/release-check.sh checks every one of these before a version is published.

#Updates

  • How they're found. Updates come through Sparkle. The feed, https://istari-ai.dev/downloads/warden/appcast.xml, is read over HTTPS only.
  • How they're checked. Each update is signed with Warden's EdDSA (ed25519) key. Sparkle refuses any update whose signature doesn't match the public key built into your copy of Warden, so a changed download can't install, even if the feed itself were tampered with.
  • What gets installed. The update is the same notarized .dmg the website offers.
  • When. Sparkle asks before installing, unless you chose to install updates on their own.

#Check your copy

The SHA-256 of the current download is on istari-ai.dev/warden. Compare it with your file:

shell
shasum -a 256 ~/Downloads/Warden.dmg

Check Apple's notarization of the .dmg. It should say accepted and source=Notarized Developer ID:

shell
spctl -a -t open --context context:primary-signature -vv ~/Downloads/Warden.dmg

Check the installed app:

shell
spctl -a -vv /Applications/Warden.app

Check who signed it. Look for TeamIdentifier=23MPNLMYKW:

shell
codesign -dv /Applications/Warden.app 2>&1 | grep -E 'Authority=Developer ID|TeamIdentifier'

#What runs on your Mac

  • Warden.app is the window. It runs only while its window is open.
  • Warden Helper lives inside Warden.app. It's a login item that runs as you: macOS lists it under System Settings → General → Login Items, where you can turn it off.
  • Sparkle's Updater runs only while an update is installing.

There are no kernel or system extensions, no privileged helper running as root, and Warden never asks for an administrator password. It isn't sandboxed, because it has to see every program's memory and act on the ones you choose. PRIVACY.md explains what it reads.

#What it can change, and the limits

  • Programs. It can move a busy program to background priority, and put it back. It stops a program only under a setting you turned on (idle AI servers, simulators, memory guards, leftovers from finished sessions), or when you click. It never quits an app, closes a window or force quits on its own. Editors, terminals, coding agents and protected programs are never stopped.
  • Files. It deletes only things that can come back. Caches, and packages and build output in finished worktrees, rebuild themselves. Installers you've already used go to the Trash. Version control must confirm a build folder is ignored or untracked, and it's asked again right before. Each of these is off until you turn it on, and if git, Mercurial or Subversion can't answer, nothing is cleared.
  • A record of every change. Every stop and clear is written to STOPPED-BY-WARDEN.md, with what was done, why, and how to get it back.
