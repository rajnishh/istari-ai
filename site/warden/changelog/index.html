#1.2.1 · 23 November 2026

Notarized by Apple. A patch for 1.2.0: AI Agents opens in seconds on Macs with tens of thousands of Claude Code conversations, and finds them in every Claude Code config folder.

#Every Claude Code config folder

  • Claude Code conversations in other config folders are listed too. People run Claude Code with several config folders, one per account or person: ~/.claude-work and ~/.claude-alex next to ~/.claude, or any folder a shell alias sets CLAUDE_CONFIG_DIR to. Warden used to read only ~/.claude. Now it finds every ~/.claude… folder that holds conversations, plus any folder named by CLAUDE_CONFIG_DIR in your shell startup files (zsh, bash, fish), and lists their conversations in AI Agents and on memory cards. Nothing to set up.
  • Resume uses the right folder: a conversation from ~/.claude-work resumes with CLAUDE_CONFIG_DIR=~/.claude-work claude --resume …, which is how Claude Code finds it.
  • Claude Code's own cleanup is read per folder: each folder's cleanupPeriodDays decides when its conversations are at risk. "Keep conversations for a year" sets it in every folder.

#Fixes

  • AI Agents → Sessions opens in seconds, even with 88,000 conversations. On a Mac where a tool starts Claude Code in a temporary folder for every task, the page showed "Reading sessions from your coding tools…" for many minutes. Reading a conversation's title and folder is now about 10 times quicker, because only the lines that can hold them are decoded. What was read is also saved, so the app and helper don't read unchanged conversations again when they start.
  • Each tool's sessions appear as soon as they're read, and the line says which one is still being read ("Reading Codex sessions…").
  • A folder with thousands of conversations lists the newest 300, with "Show all" and search for the rest. Counts and the "Archive older…" list are worked out once per load instead of on every redraw.
  • Folders on a network share no longer hold up the session list. Grouping sessions by project checks each folder for its repository. On a share that stopped answering, each check could wait a minute or more. Folders on shares are now listed as they are, without the check.
  • Services: "Nothing on watch yet" is centred on the page instead of sitting on the left.

#1.2.0 · 23 November 2026

Notarized by Apple. Everything since 1.1.0. There was no separate 1.1.1: the changes planned for it are in this release, from "Services: run a whole stack" on.

#Activity page opens in one go

  • The Activity page no longer jumps when it opens: the chart cards hold their place while the history is read, and the rest (what caused it, busiest programs, events) appears with them instead of the events first and the charts pushing in above. The charts, stretches and top lists are worked out once, in the background, instead of on every redraw.

#Settings: six tabs, and a window of their own from the menu bar

  • The menu bar's Settings… opens a Settings window of its own, with the same tabs, instead of the whole Warden window. Inside the app, ⌘, still shows Settings in the main window.
  • Six tabs: the Settings page in the main window (⌘, opens it) has six tabs across the top: General, Memory and heat, AI and sessions, Disk, Privacy and About. They replace the one long page. Each tab starts with how much of it runs on its own ("5 of 7 disk actions here run on their own"). Times and sizes are picked from plain values ("2 hours", "1 week", "When free space is below 20 GB") instead of steppers. Each section has one left-aligned line under it, with the full explanation behind ⓘ. Names match the first-run sheet. Every setting and your choices are unchanged; "Clear caches now" lives on Overview → Disk.
  • "When the Mac is slow" replaces "If the Mac is struggling" in the menu.

#AI Agents: tabs and a project tree

  • Three tabs instead of one long page: Sessions, Past work and Left running, each with a count.
  • Sessions are a tree: project (my-app, api…) → worktree, main checkout or folder → its conversations, newest first. A worktree shows its branch, PR, merge date and files; opened, its path, PR link, commits, Show in Finder, its memory card and Keep. A conversation opened shows its tool, size, folder, which session started it (side sessions) or how many it started, and Resume, Keep ★, Keep for a week or a month, Archive or Restore.
  • Folders unused for a week fold into Older than a week; merged worktrees already removed are listed under Merged and removed, with Reopen.
  • Tidying soon and Claude Code's own cleanup show at the top, each with Keep.
  • One-line rows, no empty gaps; only the rows on screen are drawn, and the tree is built in the background (about 6 ms for 60 conversations).

#Sessions and worktrees: tidied the way production tools do it

  • Only days you use the Mac count. "Unused for 30 days" means 30 days you were at the Mac: a weekend, a holiday or a week off doesn't make your work look abandoned. (Days without keyboard or mouse use, or inside Away mode, don't count.)
  • Longer, standard defaults: Claude Code sessions are archived after 30 days unused (was 7), as GitHub Codespaces; a merged worktree's folder goes after 14 days without its conversation being used (was 1 day), as Gitpod. Its packages and builds are still cleared after a day, which is where the space goes.
  • Two stages, never silent: anything due is first listed as Tidying soon (one notification, the menu bar, AI Agents) for at least a day, with Keep for a week / a month / always, and only then archived or removed. Archived sessions come back with Restore; removed worktrees keep their branch and conversation, and Reopen brings them back.
  • Parent sessions: a Claude app session that started side sessions keeps its worktree while they're still in use (from the app's own spawnedFrom record).
  • Away mode (menu bar → Pause → Going away, or Settings → AI agents): nothing archived or removed until the date, plus two days. Memory and disk protection carry on.
  • Claude Code's own 30-day cleanup: Claude Code deletes its conversations for good after cleanupPeriodDays (30 by default). Warden now says so 5 days ahead for those it lists, and Keep for a year (Settings → AI agents) sets it to 365.

#Says who turned a service off

  • Turning services on or off is logged with who asked: the Warden app, the menu bar, or warden stop (and whether a Claude Code session, Codex, Cursor or a terminal ran it, in which folder). "Stop all" is one line. Restarts and taking a service off watch say who asked too.
  • Services turned off on purpose also go in STOPPED-BY-WARDEN.md ("turned off on purpose … it stays off until started again"), where AI sessions look before starting anything again, so a stack you stopped to save memory isn't started again by mistake.

#Warns before it stops, and urgent alerts you can't miss

  • Warning first: before Warden stops something on its own that you might be using (a simulator, an idle local AI server, what a finished coding session left running), a notification says so with Keep It Running and Do It Now, and it waits 2 minutes. The menu shows it too. Kept: left alone for 3 hours. If it's used again meanwhile, the warning lapses. Close to freezing, and for Free Memory Now, there's no wait. Settings → General → "Before stopping something you may be using, warn" (0 turns it off).
  • Urgent alerts: the Mac close to freezing, the disk under 3 GB, or a service down for 2 minutes (new: a service going down used to show only in the log). These come as time-sensitive notifications with a sound, plus a small window that stays on top until you close it. Settings → General → "Show urgent alerts in a window that stays on top".
  • Free Memory Now uses the short simulator limit again (5 minutes): asked by hand, it doesn't wait the 20 minutes.

#Simulators aren't shut down while you're still using them

  • When memory is only filling up, an unused simulator now waits the usual limit (20 minutes) before Warden shuts it down. The short limit (5 minutes) applies only when the Mac is close to freezing. Before, a simulator you'd opened and were using from another window, or one an AI session was driving, could be shut down after 5 minutes of tight memory.

#Menu bar: says what's wrong, and can pause

  • Calmer icon: the same plain shield in every state, with a small orange or red dot when something needs a look (no more red or orange shield). VoiceOver hears the state ("Warden: needs a look").
  • The first row is the problem itself ("my-app tunnel can't be reached from outside"), with how many more things need a look underneath.
  • On watch: a service that isn't fine gets its own row at the top; healthy stacks fold into one row ("my-app · 5 of 5 running"), on-demand services into another. Each service has Restart, Stop and Open Log. A service that's starting shows grey, not orange.
  • Pause Automatic Actions (1 hour, 3 hours, or until tomorrow morning): for heavy work, Warden stops, shuts down and clears nothing on its own until then. It still slows programs down if the Mac overheats or nearly freezes, keeps services running, and still sends alerts. The pause survives a helper restart.

#Services: one list, grouped

  • One row per service: a status dot, uptime, memory and the health checks you set. Restart, stop and more appear when the pointer is over a row; a click shows its command, folder and latest log lines. Eight services fit on one screen instead of four.
  • Grouped by how they run, with nothing to set up: services joined by "Starts after" form a stack, named after the word their names share or their folder, with Restart all and Stop all; on-demand services and the rest get their own sections. One or two services show as a plain list.
  • Memory per service: a service's process and what it started, added up from the readings Warden already takes, every 30 seconds. A container's memory is in Docker's virtual machine, so its row says "in Docker".
  • On watch and Spotted: what Warden keeps running is "On watch" (with "6 of 8 up" and what needs a look); "Put on watch…" adds one and "Take off watch…" removes it.
  • Spotted on this Mac: below what's on watch, the Services page lists containers (Docker Desktop, OrbStack, Colima) and servers listening on a port that Warden doesn't keep running, so you can see and manage them in one place. Compose projects stay together with Restart all and Stop all. Start, stop and restart containers, see their latest log lines, open a port in the browser, or stop a server. Stopped containers are folded away. Put on watch makes one a Warden service. Nothing in this list is started at login or started again by Warden. It's looked for every 10 seconds only while the page is open, by the app, not the helper.
  • Take off watch, one or many: each stack's ⋯ menu has Take all off watch…. ⌘-click or ⇧-click rows to pick several, then Restart, Stop, Start or Take off watch from the bar at the bottom. Taking off watch leaves them running by default: Warden stops starting them at login and again when they stop, and containers and servers show under Spotted on this Mac. Take off watch and stop stops them too.

#Disk: more that can go, safely

  • Spare builds next to a running app: a Next.js app that builds into several folders (.next, .next-a, .next-b…) leaves the old ones behind, a few GB each. Overview → Disk now offers the ones nothing serves. Warden keeps the folder the running server serves (and any it has a file open in), the newest other build to go back to, and anything built in the last day, and checks all of that again before clearing. warden disk lists them too.
  • App checkpoints: Cursor keeps a copy of your files for undoing its AI edits, and on 21 Nov 2026 it wrote 18 GB of them in 15 minutes. Settings → Disk → App checkpoints (Clear automatically, Alert me (the default) or Off) clears that folder once Cursor has quit and it's over a size limit (5 GB by default), or while free space is below the caches level. Never while Cursor runs, so a checkpoint can't be cut off half-written; your files are never in that folder. Overview → Disk offers it with a Clear button when Cursor is closed, and the fast-fill alert says how to clear it. Any app with such a folder is one disk rule away ("checkpoints": true).
  • Flutter build output in idle worktrees: every worktree of a Flutter app builds everything again on its own (1 to 4 GB each). Settings → Coding worktrees → Flutter build output in idle worktrees clears it (flutter clean: build/ and .dart_tool/) in worktrees nothing runs in and nothing changed or was built in for 2 hours (adjustable), merged or not. Alert me (the default) tells you and offers it on Overview → Disk; Clear automatically does it on its own. Code and uncommitted changes stay, a build holding a release app (.aab, .ipa, a release .apk) stays, and a worktree locked with git worktree lock is never touched. Each worktree is checked again right before.
  • Old Flutter build caches: Flutter keeps a compiled copy of the app in .dart_tool/flutter_build for each way it was built (debug or release, iPhone or Android, a test run) and never removes the old ones, a few hundred MB each. Overview → Disk offers them in any Flutter project a coding session works in, worktree or not, even while it's in use: Warden keeps the newest 3 in each project and anything used in the last day. warden disk lists them too.
  • Xcode builds of projects that are gone: clearing rebuildable caches used to skip all of DerivedData while Xcode was open. It now clears the builds whose project no longer exists (a deleted worktree, say), since Xcode can't be using them, and leaves the rest until Xcode quits.

#Calmer screens

  • Programs: Quit and a ⋯ menu (Slow down, Guard) appear when the pointer is over a program, instead of three buttons on every row. Slowed-down and guarded programs show a small icon.
  • Disk → What you can do: what each item frees is a number on the right. Its cost is grey text, and orange only where it lands on you (your own files, quitting a program, a macOS update restarting the Mac). "Written lately" rows lead with the app's name.
  • AI Agents: cards show their counts ("132 cards", "18 active"), and loading says what it's reading.
  • Long explanations moved behind ⓘ in card headers.

#Disk: low-space alerts say why

  • The alert names what filled the disk. On 20 November the disk went from 23 GB free to 0 GB in a few hours: Xcode copied 11 GB of iPhone files after an iOS update. Warden only said "Only 7 GB free", every 20 minutes. Now the alert adds what grew lately, for example: "Grew in the last 7 hours: iPhone support files +11 GB."
  • It offers iPhone support files that are no longer used. Xcode keeps 3–11 GB for each iOS version an iPhone has had. While space is low, the alert names the ones for older versions and how much they take. Before, only the Disk view showed them, and only when it was opened. Deleting them is still your choice (Overview → Disk).
  • A cleanup that freed nothing isn't repeated. Clearing caches and Docker freed 0.0 GB about 15 times in two hours that day. Now one that frees less than 0.5 GB waits 2 hours before trying again, unless the disk fills 2 GB more in the meantime.
  • Disk history is kept hourly for 2 days, then every 6 hours for 14 days (before: every 6 hours for about 15 days), so a sudden fill can be timed.

#Disk Insight: what grew, for any app

  • Warden notices which folders change. macOS tells it which folders changed, once a minute, for any app, with nothing measured until it's needed. It costs no measurable CPU or memory (scripts/bench.sh checks this, now with a 5 GB write).
  • When free space drops 3 GB within an hour, Warden finds what was written. About a minute later (once macOS has passed on which folders changed), a short-lived separate process measures only those folders, follows the growth down to the folder or file that holds it, and names the app: "In the last 2 hours: Google Chrome: 6 copies of code_sign_clone (14 GB; can go once Chrome quits)". It also runs when space falls under the warning level, and when the Disk view opens.
  • Each find gets a verdict, from signals that work for any app: where it is (caches, temporary folders), copies of the same thing side by side, older versions next to a newer one, build output, whether its app is running, and whether it might be yours (your folders, projects, disk images, databases). Places macOS protects are named but never read.
  • One huge folder can't crowd out the rest. Each changed folder gets a few seconds first, and those that didn't finish get the time left over. Before, a folder like all of a project's worktrees, with one being built in, could take the whole look, and what really filled the disk elsewhere went unnamed.
  • Disk view → Written lately lists what grew, with the verdict. Caches, copies and older versions can be deleted from "What you can do"; Warden judges them again first, never while their app runs, and logs each in STOPPED-BY-WARDEN.md. Nothing new is deleted on its own.

#Disk Insight: rules for known cases

  • Known cases are described as data (rules/disk.json), and come before the generic signals: iPhone and Watch symbols (keep the newest version per device), browsers' code-sign copies (keep the newest), Cursor snapshots, the Claude app's VM, Android system images, Xcode build files, Simulator caches, Unity, Adobe media cache, Steam shaders and Spotify's cache. A matched folder gets the rule's app name, verdict and what clearing it costs.
  • Some things are marked "in use", such as the symbols for the iOS version your iPhone runs now, so Warden never offers to delete them.
  • What's yours comes with advice: Messages, Mail, Photos, iPhone backups, Docker and OrbStack name the app's own setting or command (for example, Messages → Settings → General → Keep messages).
  • Rules can be updated without a new Warden. With the update check, Warden fetches disk-rules.json. It's used only when it's signed with Warden's update key and is newer than the built-in rules. Offline mode turns this off, along with the update check. No rule can make Warden delete your own folders or places macOS protects.
  • Your own rules go in rules/local.json in Warden's folder, in the same format, and come first.

#Services: run a whole stack

On 20 November the disk filled, the Docker engine's VM stopped, and a live site's database and queue went with it. Warden ran only its tunnel, so nothing brought the rest back. Now a service can be any part of a stack:

  • Docker containers (Services → + → Container): started with the service and stopped with it.
  • Starts after: a service waits until what it needs is running, and starting it starts those first.
  • Only when I start it: for big local AI engines, never started at login or started again on its own.
  • Takes turns: services with the same group never run together; starting one stops the others and waits for them to really exit.
  • warden services and warden start|stop|restart <name> in Terminal, for people and coding agents.
  • Updating or restarting Warden never stops a service. Before, the helper stopped every service when it quit and started them again a minute later, so installing an update took a live site down. Now services keep running while the helper restarts and the new helper carries on with them. A service whose command, folder or environment changed meanwhile is started again with the new ones. Service output goes straight to its log file. Only switching a service off, or uninstalling Warden, stops it.

#Privacy

  • Settings → Privacy. Warden sends nothing about you or your Mac. The page says what it does connect to, and lets you turn each kind off:
  • the daily update check;
  • PR names from GitHub, through gh;
  • checks from outside.
  • Offline mode turns all three off. Check for Updates… still works when you choose it. It's offered on the first-run sheet too.
  • Connections Warden made: every address Warden reached, why, how many times and when, kept on the Mac. warden connections prints the same list.
  • PRIVACY.md and SECURITY.md: every connection and what's sent, what's kept on the Mac, how Warden is signed and updated, how to check your copy, and how to report a problem.
  • A test keeps the code and the policy together. It fails if the code gains a new way to reach the network without PRIVACY.md being updated, or if Sparkle's system profile is ever turned on.
  • Read window titles for Stale work (Settings → Privacy), on by default. Turn it off and Warden never reads window titles: Stale work names a window by its app alone ("Safari: a window"), and titles already read are dropped within a minute. Titles never left the Mac either way.
  • warden disk no longer asks GitHub for PR names, since it doesn't print them.

#Disk: warns on what's really free, and frees what it says

  • Alerts go by what's really free. On 15 November the disk filled and stopped a live site with no warning. Warden read Finder's figure, 37–41 GB, which counts space macOS could purge later (a waiting macOS update, caches), while 0.1 GB was really free. Now these go by real free space:
  • the warning (25 GB) and critical (10 GB) alerts;
  • the menu bar icon;
  • automatic cache and Docker clearing.

Alerts give both figures: "4.0 GB really free on disk; about 40 GB more once macOS purges what it's holding".

  • Under 3 GB really free (alerts.diskFloorGB):
  • the alert goes out at once, with a sound, even if a disk alert went out in the last 20 minutes;
  • it repeats every 10 minutes while the disk stays under;
  • clear-ups that are switched on run straight away.
  • Alerts come from Warden itself, with its name and icon, and open the dashboard when clicked. They used to go through Script Editor and were often silent. macOS asks once whether to allow them.
  • An idle Claude app session no longer keeps its worktree. An unarchived app session keeps it only while it's starred or was used in the last 24 hours (Settings → Coding worktrees). A session whose file was deleted doesn't count. From 14 to 16 November, 12 of the 15 worktrees Warden kept were kept only because of this.
  • Sizes say what deleting really frees. pnpm installs packages as copies that share their space with its store, so Warden counted about 5× too much: "Cleared 23.3 GB" freed 4.8 GB. Now:
  • it measures both what a folder takes and what deleting it would free;
  • the Disk view says "At least X GB";
  • after each clear-up, it reports the change in free space it measured.

Measuring is also faster than du, which Warden used before.

  • New build output and Finder's .DS_Store files don't keep a merged worktree.
  • Build output .gitignore missed counts only if its tool's file proves it and it holds no .aab, .apk, .ipa or outputs/.
  • Both are cleared just before git worktree remove.
  • A new .claude/launch.json alone is named in an alert, never deleted.
  • A kept worktree says the real reason. "git wouldn't remove it" no longer covers Warden's own last check.
  • Simulators one by one: each one that isn't running, with its size, when it was last used, and a Delete button. Warden never offers the running one, and won't delete one while a tool is driving simulators.
  • iPhone support files for an older iOS than that iPhone model has since run are marked No worries, each with a Delete button.
  • A waiting macOS update is named with how much space it holds, with a button to open Software Update.
  • More places looked at:
  • the SwiftPM, React Native and node-gyp caches, cleared with the other caches;
  • the Claude app's simulator builds (only builds older than a week are offered);
  • DotSlash's downloads.
  • Last read dates. AI models and the Claude app's VM say when their files were last read.
  • AI models are never cleared as caches, whatever config.json says.

#Memory: local AI models

  • A stop is said when it's done. A program deep in swap, or one finishing a request, can take minutes to stop, and Warden used to say "Stopped" at once. Now:
  • quick stops read as before;
  • one still running after a few seconds is "finishing its current work", and Warden says when it has stopped;
  • one still running after a minute gets a Force stop on Overview, which asks first and says what's lost.

This covers every stop Warden makes: idle AI servers, memory guards, Free memory now, and what finished sessions left running.

  • One big AI model at a time. Two big models running at once don't share the Mac: each slows the other down, and swap fills. In one test a picture took 260 s instead of 40 while a background job had a model loaded in Ollama.
  • When a second big model runs, Warden unloads an Ollama model that's sitting idle. Ollama loads it again on its next request, so nothing is lost. This is on by default; Settings → AI agents turns it off.
  • Anything busy is only named, with how to free it.
  • Any program counts: a local AI server Warden knows, or any command-line program holding 2 GB or more of GPU memory, such as a Python service running a model on the GPU.
  • Warden asks Ollama only on this Mac, on the port its server listens on.
  • When a service stops answering while big models hold memory, the alert names them. An idle Ollama model is unloaded if memory is short.
  • A container engine going down is said. When Docker Desktop, OrbStack, Colima, Rancher Desktop or Podman stops answering twice in a row while containers were running, an alert names the containers that are down, and the menu bar icon turns red.
  • Programs → Start starts the engine with its own tool, then the containers that were running and didn't come back by themselves.
  • If the engine comes back without some of them, those are named too.
  • Settings → Disk → "Start Docker and its containers again if the engine stops" does this on its own. It's off until you turn it on, since an engine stopped on purpose would come back.
  • AI models that are partly gone are named. This covers a Hugging Face model whose links point to deleted files, and an Ollama model whose manifest names a missing file. The next run would download them again in full. They're shown in the Disk view and in warden disk; Warden never changes a model folder.
  • A folder holding AI model weights is never cleared as a cache, wherever it is and whatever it's called. Warden looks for .safetensors, .gguf, .ckpt, .pt, .onnx and the like.
  • GPU memory isn't called swap. A model running on the GPU counts in a program's memory, but isn't in RAM, so Warden used to report it as "pushed out to swap". What's compressed or in swap is now read from the program itself.

#Fixes

  • Only one helper runs at a time. A second copy used to start whenever the helper was run by hand, or after a mistyped warden command such as warden --version. Both copies then ran every check, alert and disk round, and stopped each other's services. Now each helper takes a lock in Warden's folder, and a second copy stops before doing anything, saying which one is already running. The lock goes when the helper does, even after a crash, so it can't keep Warden from starting.
  • A mistyped warden command prints the list of commands instead of starting a helper.
  • warden version (also --version or -v) says which Warden this is. --help and -h print the commands.

#1.1.0 · 14 November 2026

Notarized by Apple. Everything since 1.0.0 (built 11 November).

#Disk: watched in the background, and finished work tidied safely

  • The disk is watched in the background. Free space is read every hour. A full measurement runs every 6 hours, half an hour after free space drops 5 GB, and whenever the Disk view opens.
  • The forecast ("full in about 3 days") uses the last day's pace. A sudden drop whose space comes back within 3 hours (a build, a virtual machine's swap) doesn't count.
  • Growth alerts name what grew, and the biggest worktree with its build output.
  • Finished coding worktrees give back their space. A worktree counts as finished when all of these hold:
  • its work is merged into main;
  • nothing in it changed;
  • nothing runs inside it, and it isn't open in an editor;
  • nobody touched it for an hour.

Its packages and build output can then be cleared, and come back with pnpm install or a build. Settings → Coding worktrees: Clear automatically, Alert me (the default) or Off.

  • Build output for every major language: node_modules, Maven and Gradle (target, build, .gradle, .kotlin), Rust target, .NET bin/obj, Python .venv and caches, Elixir, Haskell, Zig, CMake, Flutter, Ruby vendor/bundle, PHP vendor, Terraform, Unity, Unreal, iOS Pods, and Next, Nuxt, SvelteKit, Angular and Parcel output. A folder is offered only when two things hold: its tool's own file is beside it (pom.xml, Cargo.toml, composer.lock…), and version control ignores it or doesn't track it.
  • Merged worktrees that hold nothing else can be removed. This is opt-in; Alert me is the default. It happens only after the worktree's memory card is saved, with no live session in it, and with no file in it changed today. Removal is git worktree remove, never forced.
  • Memory cards and Past work.
  • A card for every merged worktree: the PR, commits, changed files and every conversation held there, from Claude Code, the Claude app, Codex, Gemini CLI, Cursor, Copilot CLI, Amp, OpenCode, Aider and more.
  • Reopen makes the worktree again and continues its conversation.
  • Cards for work outside worktrees too: main checkouts, feature branches and plain folders such as docs, with their sessions, commits, uncommitted files and resume commands. Warden never removes these folders.
  • It knows what's open in your editor. A folder open in Cursor, VS Code, Windsurf, VSCodium, Kiro, Trae or a JetBrains IDE (IntelliJ, PyCharm, WebStorm, GoLand, CLion, Rider, Android Studio…) counts as in use, even with nothing running in it.
  • Mercurial and Subversion, as well as git. Jujutsu's colocated repositories are read as git.
  • Installers you've already used (a .dmg, .pkg, .zip or .xip in Downloads whose app is installed) can go to the Trash. Off by default.
  • warden disk prints where space goes, what's safe to free and which worktrees would go and why, and changes nothing.

#Memory: when the Mac is close to freezing

  • The menu bar icon opens at once even then. In a test with every core busy and memory at warning it opened in under 5 ms; before, a click waited 22 seconds to 2 minutes.
  • Free memory now offers real choices once the safe steps are done: idle local AI servers, dev servers and test runs per project, idle coding sessions, and the biggest apps. Each asks first and says what could be lost. The Memory card has an Automatic switch.
  • The menu's "If the Mac is struggling" section offers local AI servers. Force Quit asks first, and never offers Claude, Finder or Warden.

#Services

  • A service that's already running outside Warden (started in Terminal, say) is adopted instead of being started twice, including when you switch a service on.
  • The check on this Mac is a plain request over a socket. It follows redirects to another page on this Mac, as before.

#Lighter

  • About 8× fewer wakeups. A health check kept an HTTP/3 connection open, and macOS pinged it every second or so.
  • About half the CPU, a fraction of a percent of one core.
  • Less memory: about 20–30 MB, and a disk check peaks around 30 MB instead of 100.
  • Fewer disk writes:
  • status is saved every 2 seconds while the dashboard is open, after a reading in which something important changed, and otherwise every 2 minutes;
  • the minute-by-minute history is written in batches while the Mac is calm, and every minute while it's under strain.
  • The stuck-app check: the app in front is asked every 10 seconds, and other apps every 30.

#Safer

  • When git, Mercurial or Subversion can't answer (Xcode's licence not accepted after an update, a broken install, a stuck command), nothing is offered for clearing.
  • Version control is asked again right before anything is deleted.
  • A worktree git can't read counts as changed.
  • A worktree that any program changed today is kept.
  • An archived Claude app session's worktree may go after an hour, not a day.

#Fixed

  • A health check with an impossible port no longer stops the helper.
  • A crash when Free memory now refreshed its choices.
  • An update could leave the helper stopped.
  • Menu bar apps starting or quitting (OrbStack, say) are noticed at once.
  • Siri and the terminal no longer read out an old status when the helper isn't running.
  • After clearing packages, Warden says pnpm install, not npm install.
  • Processes macOS refuses to describe are skipped instead of asked about on every reading.

#1.0.0 · 12 November 2026

The first release, notarized by Apple.

  • First run: you choose what Warden does on its own. Everything that stops a program or deletes files starts off.
  • Services: keeps any command running (dev servers, APIs, workers, tunnels). It restarts them, checks them on this Mac and from outside, and can take over one already running.
  • Heat and CPU: the busiest programs are moved to background priority while the Mac is hot or CPU stays high, and put back when it's calm.
  • Memory and swap: alerts that name the biggest programs and what started them; memory guards; acting at the first sign of a freeze (slowing a program that grows fast).
  • AI agents:
  • idle local AI servers and unused simulators are stopped;
  • one list of coding sessions, with archive and restore;
  • servers a finished session left behind are tidied up;
  • every stop is written to STOPPED-BY-WARDEN.md.
  • Stale work: sessions, apps and windows left open and unused, with what they hold.
  • Disk: rebuildable caches are cleared when space is low; the Disk view says what's safe to free; build folders in finished projects are suggested.
  • Docker, OrbStack and Colima: containers, what they hold, and clearing what rebuilds.
  • Activity: charts of CPU, memory, swap and disk, and what caused each spike.
  • Apps not responding: an alert with the likely cause.
  • Siri and the terminal: warden status, why, cool and free.
  • Updates through Sparkle.
