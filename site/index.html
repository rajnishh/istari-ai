How it works

From ticket to pull request, with a supervisor in the loop

The agent writes the code. Istari runs the process around it: it gathers context first, checks the work itself instead of trusting the agent, and stops for you where it matters.

  1. Enrich

    Ticket, comments, parent epic, attachments and related past work.

  2. Plan

    A plan, pressure-tested by a critique pass.

    Optional approval

  3. Implement

    In an isolated git worktree with its own ports.

  4. Verify

    Istari runs build, lint and tests itself, and loops on failures.

  5. Review

    A second pass reviews the diff; concerns go back for fixes.

  6. Deliver

    Secret scan, scope check, then push and open the PR.

    Optional approval

  7. Watch

    Follows CI to green. Never merges on its own.

Where you can make it stop and ask

What you get

Built for the work around the code

Memory across sessions

Decisions, lessons and past work are captured as you go and brought back at the start of the next session, whichever engine you use.

Recall that cites its sources

ist recall "what did we decide about auth?" searches sessions, decisions, PR reviews and meeting notes, and refuses when nothing relevant exists.

Safety limits

Budgets with a kill switch, loop detection, trust levels, approval gates and a mutation gate on automated writes to GitHub and JIRA.

Parallel agents, no collisions

Each task gets its own git worktree, ports and environment, so several agents can work side by side.

Background PR review

Reviews pull requests where your review is requested, with code, security and architecture passes, and learns your review style.

Local review first

ist review reviews the branch in front of you, on your machine, and posts nothing anywhere.

Automation you describe

"When this, then that" workflows in YAML: PR watchers, CI monitors, daily standups, bug patrol.

An inbox for engineers

PR requests, reviews, merges and assigned tickets in one feed, in your terminal and your editor's status line.

Control from your phone

An optional Discord bot to check agents, answer approvals and search memory while you are away.

Trust

Exactly what it changes on your machine

Istari hooks into your AI tools, so it tells you up front what it touches, asks before it writes into config you own, and can put everything back.

Its own folderEverything it stores lives in ~/.istari/: a SQLite database, config and logs.
Hooks, only if you say yesist setup lists every file it would write, such as ~/.claude/settings.json, and asks before installing.
Reversibleist hooks off pauses everything. ist uninstall shows a dry run, then removes exactly what it added.
No telemetryIt sends nothing to its authors. It only talks to the services you connect.

Questions

Good to know

Is it free?

Yes. Istari itself is free. You pay only for the AI engines and services you already use.

Is it open source?

Not yet. The source code will be published under the Apache 2.0 licence once it is ready. Releases, issues and security reports are public today.

Which platforms?

macOS on Apple Silicon, and Linux on x64 and arm64. On Windows, run it inside WSL2: wsl --install, then the same install command in your Linux shell. Intel Macs can install with Homebrew: brew install rajnishh/istari/istari.

Which tickets and engines?

Claude Code has the deepest integration; Codex, Cursor and Ollama are supported. Ticket integration targets JIRA today.
