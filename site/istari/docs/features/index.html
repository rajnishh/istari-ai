    Use Istari

    Features

    This page follows ist guide in the CLI, so the words match what you see in your terminal. ist <command> --help has the full detail for each command, and the command reference lists them all.

    #Review pull requests

    #ist reviews

    The control panel for PR review. It shows every PR in the review lifecycle with its state, how many rounds it has been through, and what it cost.

    CommandWhat it does
    ist reviewsList everything currently in review.
    ist reviews --pause <pr>Stop reviewing one PR without turning the reviewer off.
    ist reviews --resume <pr>Put it back in the queue.
    ist reviews --approve <pr>Approve from the terminal.

    #ist pr-digest

    One screen of every PR in the lifecycle, grouped into waiting, stale and escalated, so you can see which review is blocked on a person rather than on an agent.

    #ist pr-summary

    During review the agent writes a technical summary of what the PR does. This opens it, which helps when you are the second reviewer and don't want to rebuild the change from the diff.

    #ist kb

    Every review is archived and searchable, with the subcommands show, search, stats, diff, review and thread. Use it to answer "have we hit this bug pattern before?" without rereading old PRs.

    #ist watch

    Background watchers for PR review, bug triage and CI, with start, stop, status and list.

    Turn watchers on deliberately. They act when you are not there: a PR watcher posts real comments on real pull requests. Start with one repo and ist trust supervised until you have seen it behave.

    #ist workflow

    "When this, then that" workflows: list, show, create, run, enable, disable, preset and set. Presets cover the common shapes, so you rarely write one from scratch. The workflow catalog lists every trigger, action and template.

    #Get work done

    #ist go

    Start here every morning. It answers "what should I work on?" by combining your tickets, your open PRs and what you left unfinished. If you learn one command, learn this one.

    #ist board

    Your JIRA tickets in the terminal, without the browser tab.

    #ist pick

    Hands a ticket to an agent. It creates an isolated worktree, plans, implements, verifies with your own build and tests, and opens a PR. Watch the first few with ist logs, and keep ist trust at supervised until you trust the output.

    #ist start, ist chat and ist tell

    Work alongside an agent.

    CommandWhat it does
    ist startAn interactive session with Istari's context and memory attached.
    ist chatA two-way conversation with an agent that is already running.
    ist tellA one-way instruction to a running agent, so you can carry on.

    #ist status, ist logs, ist resume and ist kill

    See and recover running work. ist status lists running tasks and sessions with their repo and age. ist logs streams one. ist resume recovers a crashed or frozen agent. ist kill stops one.

    #Find things you already knew

    #ist recall

    Searches archived work (past sessions, decisions and PR reviews) and answers in prose with citations.

    Known rough edge. On questions with no relevant history, the answer can still sound confident. Treat the citations as the truth, not the prose. This is a known open bug, not a problem with your setup.

    #ist ledger and ist note

    Make a decision last. ist note records a decision from inside the current session. ist ledger is the lasting, structured store, with add, last, list, show and reindex. The point is finding it months later: "why did we choose this?" answered from the record instead of from memory.

    #ist graphify

    Builds a knowledge graph of a repo, so agents can look up structure (callers, dependencies and what a change could break) instead of reading whole files. That is where the large token savings come from on big repos. See graph-first reviews.

    #Keep an eye on things

    #ist cost and ist analytics

    ist cost breaks token spend down by ticket and by day. ist analytics is the wider view of what got done. Run ist cost after your first week: it is the fastest way to spot a watcher you left running.

    #ist feed

    A personal engineering inbox: review requests, CI failures, ticket changes and session events in one list, with open, pick, snooze and dismiss. ist inbox is the interactive browser for it.

    #ist dashboard

    A local web dashboard, with start, stop, restart and status, for people who would rather see it than type it. It serves on localhost and starts only when you ask.

    #Tune it

    #ist trust

    The most important setting in Istari. It has four levels:

    LevelBehaviour
    interactiveAsks before acting. Slowest and safest.
    supervisedActs, but checks in before anything outward-facing. Start here.
    autonomousActs without asking. Use it once you trust a given workflow.
    silentAutonomous and quiet. For things you have already watched work.

    #ist routing and ist account

    ist routing picks which engine handles which job, with show, set, reset, doctor and trace. trace explains why a task went where it did. ist account manages parallel Claude Code accounts; see multiple accounts.

    #ist config

    get, set and list for everything else. Unknown keys are rejected rather than written, with a suggestion for what you might have meant, so a typo can't quietly turn a feature off.

    shell
    ist config                       # view everything
ist config review                # PR review settings
ist config currency AED 3.67     # show costs in your currency
