    Get started

    Setup

    #First run

    One command, about three minutes. You can run it again at any time: it never overwrites answers you already gave.

    shell
    ist setup
    output
      ISTARI - The Intelligence Layer for Engineering Teams

    Three questions. Takes about a minute.

    Step 1/3 - What's your role?
      [1]   Technical - Writes and ships code
      [2]   Non-technical - Reads code, writes docs and tickets
      [0]   Skip - use defaults (Technical)
    StepWhat happensCan you skip it?
    Your roleTechnical or non-technical. It sets permissions and the per-agent budget, decides which agent templates are installed, and shapes what ist go puts in front of you.Yes, press 0
    Your environmentFinds installed engines (Claude Code, Codex, Cursor, Ollama), the GitHub CLI and any MCP servers, then asks which of them Istari may use.Detection is automatic; using each tool is your choice
    HooksLets Istari observe your agent sessions so it can learn and recall. It lists the files it would touch before it writes anything.Yes

    When there is a real choice of engine, setup asks. One usable engine is registered automatically, several prompt you, and a choice you already made is left alone. An engine that is installed but not logged in cannot run anything, so it is left out rather than chosen silently. You can override the engine per feature later with ist routing.

    Declining hooks writes nothing at all. You can run ist install-hooks later if you change your mind. What you give up: recall, cost tracking and the inbox can't see your sessions, so they stay empty. ist review needs no hooks and works either way.

    #What setup leaves for later

    Setup ends by listing what is not configured yet, with the one command for each. None of it is asked up front, because on a first run you mostly don't have the answers yet.

    Not configuredThe command
    JIRAist config tickets.url <url>
    Discordist setup discord
    GitHubgh auth login
    Memory from your existing AI filesist bootstrap
    Workspaces for the repos on this machineist workspace suggest

    #Connect your tools

    #GitHub

    Do this one. Everything to do with pull requests runs through the GitHub CLI, using your own account.

    shell
    gh auth login     # browser flow, once
gh auth status    # confirm

    #Claude Code

    If claude is installed and logged in, Istari finds it, and there is nothing to configure. Check it with ist doctor, under Agent Engines.

    #JIRA and Discord

    Both are optional. JIRA gives you ist board and ticket-aware agents. Discord gives you a thread per PR where reviews and approvals show up. You'll need a JIRA API token and a Discord bot token. Setup tells you where each value goes and writes them to a local file that only your user can read.

    #Prerequisites

    Istari itself needs nothing. These tools are for the work it does, so install what you want to use and skip the rest.

    ToolNeeded forGet it
    gitRequired: everything is repo-awareAlready on macOS (or xcode-select --install)
    claudeAgents: the engine that does the workclaude.com/claude-code
    ghPR features: review, watch, approvebrew install gh

    You don't need Bun, Node or Python. If you ever see an error that mentions bun, that's a bug worth reporting with a support bundle.

    #Confirm it worked

    ist doctor is the honest answer to "is this thing configured?" It lists what is present, what is missing, and what still works without it.

    shell
    ist doctor
    output
    Istari Health Check
──────────────────────────────────────────────
Agent Engines
  ✅ Claude Code          2.1.225 → ~/.local/bin/claude
  ✅ Codex CLI            codex-cli 0.146.0
  ✅ Cursor CLI           installed
  ✅ Ollama (local LLM)   running

  ✅ Discord              gateway running (bot connected)

  ⚠  Agent assets         not scanned yet (run `ist assets scan`)

    Run it again after you connect anything.

    #Go live with the background service

    The background service is what makes Istari feel automatic. It polls your PRs, dispatches reviewer agents, watches CI and fills your inbox. Without it, Istari only does what you type.

    shell
    ist daemon start     # start the supervisor
ist daemon status    # running? since when?
ist daemon stop      # when you want quiet

    Run ist daemon install to start it at login. It restarts itself if it crashes. Its logs live in ~/.istari/logs/, which is what a support bundle collects.
